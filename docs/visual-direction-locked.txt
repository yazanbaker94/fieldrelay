We have now finalized the visual direction for FieldRelay. Do not redesign it into a conventional SaaS dashboard.
I am attaching reference designs. Treat them as the visual source of truth for art direction, composition, density, typography, hierarchy, and brand character. The existing FieldRelay product/engineering brief remains the source of truth for functionality, business logic, states, data, and flows.
The design concept is:
“Dispatch Ledger / Instrumented Chain of Custody.”
FieldRelay should feel like a combination of:
-  an industrial field instrument, 
-  a shipping/dispatch manifest, 
-  an operational reconciliation ledger, 
-  and a developer-grade recovery console. 
It must feel authored and unmistakably FieldRelay, not like a generic SaaS template.
The recurring visual signature is a thin connected event/relay line with numbered nodes:
01 → 02 → 03 → 04 → 05 → 06
Reuse this language throughout:
-  shipment lifecycle, 
-  homepage story, 
-  exception evidence, 
-  delivery retry attempts, 
-  guided-demo progression, 
-  mobile workflow, 
-  audit timeline, 
-  architecture diagrams. 
Also use FieldRelay record notation as a branding device:
FR / 2026 / 0842
EX / 0037
DL / 019
EV / 0347
These IDs should sometimes appear oversized or in gutters, almost like engineering drawing / dispatch indexing.
Do not drift into:
-  generic SaaS hero layouts, 
-  floating laptop + phone mockups, 
-  glassmorphism, 
-  gradients everywhere, 
-  huge rounded cards, 
-  pill badges everywhere, 
-  four identical KPI cards as the main visual language, 
-  decorative blobs, 
-  fake testimonials, 
-  fake customers, 
-  fake enterprise logos, 
-  giant empty whitespace, 
-  “AI startup” typography, 
-  stock dashboard templates, 
-  generic truck/barrel/shield logos. 
Do not make every section a card.
Use rules, alignment, typography, spacing, event rails, document structure and actual operational data to create the composition.
Use:
IBM Plex Sans
for normal interface text, long-form text, form labels and mobile usability.

Base direction:
-  warm paper/background: around #F7F5F0

Most of the product should remain neutral.
Color must be earned:
-  orange = actionable discrepancy/warning 
-  red = real failure 
-  green = confirmed recovery/success 
-  blue = interaction/product identity 
-  violet = simulated/demo controls only 
Never depend on color alone.
-  low radius: roughly 4–8 px web

-  almost no shadows 
-  thin borders/rules 
-  flat surfaces 
-  strong grid alignment 
-  no cards inside cards unless structurally necessary
